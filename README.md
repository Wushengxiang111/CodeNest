# NETDISK

NETDISK 是一个使用 C 语言实现的 Linux 客户端/服务器项目，提供基础的网络文件存储和简易代码版本管理功能。客户端与服务器通过 TCP Socket 通信；服务器使用 pthread 为客户端连接创建线程，并使用 SQLite 保存账户、操作历史和代码仓库元数据。

> 本项目主要用于学习 C 语言、Linux 文件操作、TCP Socket、多线程和 SQLite。当前实现没有针对公网生产环境进行安全加固，请勿直接暴露到不可信网络。

## 功能

### 用户与文件

- 注册、登录和退出。
- 查看当前账号的文件列表。
- 上传本地文件到服务器。
- 下载服务器文件；如果本地已有同名文件，可以选择从本地文件长度处继续下载。
- 查询当前账号的操作历史。
- 注销当前账号。

### 代码仓库与版本

- 创建代码仓库并填写名称和描述。
- 查看当前账号拥有的仓库及其 ID、描述和当前版本。
- 将一个本地代码文件提交到指定仓库，并填写提交说明。
- 查看仓库提交历史。
- 下载指定版本的文件。

每次提交保存的是一个文件版本，不是完整的 Git 仓库或多文件目录快照。

## 技术与依赖

- C 语言，Linux/POSIX 环境
- TCP IPv4 Socket
- pthread
- SQLite3
- 标准 C 文件 I/O 与 Linux 文件系统操作

在 Debian/Ubuntu 上可安装构建依赖：

```bash
sudo apt update
sudo apt install build-essential libsqlite3-dev
```

## 编译

在项目根目录执行：

```bash
gcc -Wall -Wextra -std=gnu11 client/client.c -o client/client -pthread
gcc -Wall -Wextra -std=gnu11 server/server.c -o server/server -pthread -lsqlite3
```

编译器生成的 `client/client` 和 `server/server` 可执行文件已列入 `.gitignore`，不会作为源码提交。

## 运行

服务器固定监听 TCP `8888` 端口。先在项目根目录启动服务器：

```bash
./server/server
```

然后在另一个终端连接服务器。`127.0.0.1` 用于客户端和服务器运行在同一台机器的情况：

```bash
./client/client 127.0.0.1 8888
```

局域网客户端应将 `127.0.0.1` 替换为服务器的 IPv4 地址，并确保防火墙允许访问 TCP `8888` 端口。客户端参数格式为：

```text
./client/client <服务器IPv4地址> <端口>
```

服务器会在**启动时所在的工作目录**创建或使用 `netdisk.db`、用户文件目录和 `repositories/`。因此请从希望保存数据的目录启动服务器；在项目根目录启动时，数据大致如下：

```text
NETDISK/
├── netdisk.db            # SQLite 数据库
├── <用户名>/              # 用户上传的文件
└── repositories/
    └── <仓库ID>/
        └── versions/
            └── <版本号>/  # 提交的文件版本
```

`netdisk.db` 会被 `.gitignore` 忽略；用户目录和 `repositories/` 目前不在忽略规则中。运行后请检查 `git status`，避免把数据文件误加入代码仓库。

## 客户端菜单

连接后按提示输入菜单编号：

| 编号 | 操作 | 说明 |
| ---: | --- | --- |
| 1 | 注册 | 创建账号 |
| 2 | 登录 | 登录账号 |
| 3 | 文件列表 | 查看服务器上当前账号的文件 |
| 4 | 下载文件 | 下载文件；同名本地文件可选择续传 |
| 5 | 上传文件 | 上传当前目录中的本地文件 |
| 6 | 操作历史 | 查看文件操作历史 |
| 7 | 注销账号 | 注销当前登录账号 |
| 8 | 退出 | 关闭客户端 |
| 9 | 创建代码仓库 | 输入仓库名称和描述 |
| 10 | 我的代码仓库 | 查看仓库 ID、名称和版本 |
| 11 | 提交代码 | 输入仓库 ID、文件名和提交说明 |
| 12 | 查看版本 | 查看指定仓库的提交版本 |
| 13 | 下载版本 | 选择仓库后查看版本，并输入要下载的版本号 |

上传和代码提交时，客户端会从**客户端当前工作目录**读取指定文件；下载文件则写入客户端当前工作目录。请确保客户端进程对相应目录有读写权限。

## 文件传输与版本行为

- 文件上传按固定大小的数据块发送，服务器将文件保存到以用户名命名的目录中；同名服务器文件会被覆盖。
- 下载时，如果客户端当前目录已存在同名文件，客户端可选择继续下载；程序把本地文件长度作为服务器端读取起点。
- 代码提交通过仓库 ID 标识目标仓库。每次成功创建提交会生成递增的版本号，并保存提交说明、时间和文件路径。
- 版本下载需要仓库所有者权限，下载出的文件保存在客户端当前工作目录。

## 通信协议

客户端和服务器共享 [`common/protocol.h`](common/protocol.h) 中定义的 `struct net_info`。结构体包含请求类型、用户名、密码、文件名、数据缓冲区、仓库 ID、版本号和提交说明等字段；`send_all`、`recv_all`、`send_packet` 和 `recv_packet` 是该头文件提供的传输辅助函数。

| 请求类型 | 名称 | 用途 |
| ---: | --- | --- |
| 1 | `TYPE_REGISTER` | 注册 |
| 2 | `TYPE_LOGIN` | 登录 |
| 3 | `TYPE_LIST` | 查看用户文件 |
| 4 | `TYPE_GET` | 下载用户文件 |
| 5 | `TYPE_PUT` | 上传用户文件 |
| 6 | `TYPE_HISTORY` | 查看操作历史 |
| 7 | `TYPE_DELETE_ACCOUNT` | 注销账号 |
| 8 | `TYPE_EXIT` | 退出 |
| 9 | `TYPE_CREATE_REPO` | 创建代码仓库 |
| 10 | `TYPE_LIST_REPO` | 查看用户仓库 |
| 11 | `TYPE_COMMIT` | 提交文件版本 |
| 12 | `TYPE_LIST_VERSIONS` | 查看仓库版本 |
| 13 | `TYPE_DOWNLOAD_VERSION` | 下载指定版本 |

当前协议直接在 TCP 连接上传输 C 结构体，适用于本项目配套的客户端和服务器，不是跨平台或网络协议标准。不同编译器、CPU 字节序或结构体对齐方式可能导致不兼容。

## 数据存储

服务器使用工作目录中的 `netdisk.db` 保存 SQLite 数据。主要数据包括：

- `user_info`：用户账号信息。
- `history_info`：用户查看文件列表、下载和上传的操作历史。
- `repositories`：代码仓库名称、所有者、描述和当前版本。
- `commits`：提交版本、说明、时间及对应文件路径。

用户上传文件保存在工作目录下以用户名命名的目录；代码版本文件保存在 `repositories/<仓库ID>/versions/<版本号>/`。

## 当前限制与安全提示

- 客户端和服务器通信使用未加密的 TCP；账号密码以明文方式存储，且当前实现将输入拼接进 SQL 语句。请仅在可信的本机或实验网络中测试，不要使用真实密码或将服务直接暴露到公网。
- 服务端监听端口目前在代码中固定为 `8888`。
- 代码仓库版本管理面向单文件提交，不提供 Git 的分支、合并或多文件提交功能。
- 注销账号会删除账号、操作历史和用户文件目录；当前实现不会清理该账号创建的代码仓库及其版本文件。
- 文件及仓库数据使用相对路径保存，服务器工作目录会影响数据实际位置。
